# 兩種錢:局內的魂,和帶得回家的東西

> **命名對照(2026-09-08 之後)**:文件正文保留當時的用詞,因為改掉會讓當時的推理讀不通。
> 現在遊戲裡顯示的是:**魂 → 燼**、**篝火 → 爐**、**火防女 → 守夜人**。
> 識別碼(`T.BONFIRE`、`p.souls`、`key: 'firekeeper'`)沒有改,見 `docs/NAMING.md`。


> **狀態:第一階段(兌換所)已實作。** 死亡改回廳堂、局外強化改用灰購買,還沒做。
>
> 已經在遊戲裡的:**燼**(局內,死了就沒)、**灰**(廳堂,永久)、爐邊的兌換,
> 以及隨深度上升的匯率。這份規格會推翻兩個寫下來的決定,兩個都在下面點名。
>
> 它也是一次**類型上的轉向**:從「技術就是成長」變成「反覆挑戰累積體質」。
> 那不是調參數,所以理由要寫清楚。

## 它從哪裡來

第一次有人通關,而且是**零死亡**,71 殺、1342 回合、八分鐘。

同一輪裡,玩家**一次升級都沒買**。量了之後發現原因不是買不起:

| | |
| --- | --- |
| 把十層敵人全殺光 | **910 魂** |
| 那一輪殺了 71 隻 | 大約 550～600 魂 |
| 「氣」第一階 | **40 魂**(全清的 4.4%) |
| 兩條線全滿 | 2340 魂 = 2.6 次全清 |

**魂不缺,升級也不貴。買了沒感覺才是問題**——兩條線給的是「精力上限 +2」和「免費重量 +2」,那是小數點,不是誘因。

而遊戲的設計前提寫著「你會失敗幾次才通得過」,實際上第一次就無傷過了。**這兩件事一起說明:局內的成長線沒有在做事,而難度沒有底。**

## 兩個被推翻的決定

**一、`DESIGN.md`:「零升級必須能通關,而且那是一條測試」。**

那條測試的理由是:

> 敵人會在坐火之後全部復活,所以任何「必要的貨幣」都會讓刷變成最佳解,而不只是可行。

**這個顧慮是對的,而且是這份規格最重要的約束。** 見〈刷〉。

**二、`META.md`:「局外進展不給任何數值。不是不能,是不要。」**

它的理由是:所有平衡工作都建立在「玩家的能力來自裝備和判斷」上,一個給數值的局外系統會
**不可測地**弄髒每一個量過的數字。

推翻它的條件是**天花板不動**:

> 現在的體質就是終局的體質。局外進展是在下面接一段坡,不是往上灌水。

這樣所有量過的數字都還算數——它們描述的是**終點**。代價是早期變成沒量過的地方,
見〈量不到的東西〉。

## 形狀:兩種錢

| | **燼**(embers) | **灰**(ash) |
| --- | --- | --- |
| 哪裡拿到 | 殺東西 | **用魂買** |
| 存在哪 | 身上 | 廳堂 |
| 死了 | **全部沒了** | 不受影響 |
| 買什麼 | 全域貨幣、局內消耗品 | 局外強化 |

**爐是兌換所。** 你走到爐邊,把身上的燼燒成灰。沒燒的,死了就沒了。

名字是實作時定的,而且它自己就在講這件事:**燼是火燒剩下還有餘溫的東西,灰是它涼掉之後
留下的。** 熱的會消失,涼的留著——而廳堂本來就叫**灰燼之廳**。

這一條就是整個設計。其他都是它的推論。

### 為什麼是「買」而不是「存」

存款是保管,購買是**匯率**——而匯率是一個旋鈕。深層的火可以給更好的匯率,
危險的位置可以給更好的匯率,而「要不要再深一層再換」因此是一個有數字的決定,
不是一個感覺。

## 刷:這份規格的主要約束

原本的顧慮成立,而且在新架構下**更嚴重**,因為刷來的東西現在是永久的。

如果照最直覺的做法(死了東西照樣帶回家 + 篝火照樣讓敵人復活),最佳打法是:

> 走到第一層的火,清一次,坐下,敵人復活,再清一次。永遠不用往下走。
> 萬一死了,反正東西照樣帶回家。

**零風險、無限產出、永久收益。** 那不是數值問題,是支配策略。

擋它的就是「**魂死了就沒了**」這一條:

- 刷第一層可以,但你得**活著走回火邊**才換得到東西
- 而第一層的魂本來就少,每小時的產出爛到不值得
- 往下走產出高,但**沒換就死等於白跑**

所以每一座火都是一個真的決定:**現在換,還是再深一層。** 這正是原本的
「死亡會掉下上次休息之後拿到的一切」想做的事,只是把「掉在原地可以撿回來」
換成「就是沒了」。

## 四個條件,逐條的後果

**1. 魂變成局內貨幣,全域貨幣另外命名。** 火防女和篝火一起改名,見 `docs/NAMING.md`。

**2. 死了直接回廳堂,不回篝火。** 篝火不再是重生點,只是補給和兌換的地方,
使用後敵人照樣復活。

> 敵人復活這條**留著,而且意義反過來了**。它現在不是「重置的代價」,是
> 「你換錢的代價」——你想再換一次,得先再打一次。

**3. 只有換過的帶得回家。** 背包裡沒換的非消耗品和身上的魂,死了一起沒。
穿在身上的裝備不受影響(這條和現在一樣)。

**4. 局外強化伴隨更深的地城。** 這條是最貴的,見下面。

### 魂也要有局內的用途

不然它只是「還沒變成經驗值的經驗值」。

火邊可以**直接用魂買消耗品**(藥、投擲物、臨時詞條)。這讓「換成全域貨幣」有了對手:
同一筆魂,是現在買一瓶藥活過這一層,還是帶回家變成永久的一點體質?
**那是這個系統裡最好的一個決定,而它不用另外設計,只要讓兩個選項共用同一個錢包。**

## 更深的地城:先擴敵人,再加層數

量出來的:

| | |
| --- | --- |
| 敵人種類 | **11 種** |
| 最深的新敵人 | **第 7 層**(牛頭人) |
| 第 8、9、10 層 | **沒有任何新東西** |
| 王 | **1 個** |

所以「往下加層」現在只會得到「同一場仗、更多隻」,而那正是設計文件明確拒絕的事
(「數量不是難度旋鈕,組成才是」)。

**順序是:先有更多敵人,才有更深的地城。** 粗估一階需要三種新敵人 + 一個王 +
一張王廳板塊,而王廳那件事剛好接上 `DESIGN.md` 裡擱置的〈王廳要不要獨立於迷宮〉。

那是清單擴張,不在這份規格裡。

## 分三個階段做

**第一階段:兌換所。(已完成)** 只做兩種錢和那條兌換,不動層數、不動敵人。

實測的匯率:第 1 層 **10%**、第 5 層 46%、第 10 層 **91%**。500 燼在頂層換到 50 灰,
在底層換到 454——**九倍**,所以「在第一座爐前面刷」是全遊戲最差的匯率。

**第一階段:兌換所。** 只做兩種錢和那條兌換,不動層數、不動敵人、不改名。
局外強化先只接現有的兩條線(氣、負重),而且**天花板就是現在的數值**——
也就是說一開始你比現在弱,練滿之後就是現在。

這一階段自己就是完整的、可以玩的、可以量的。

**第二階段:命名 pass。** 見 `docs/NAMING.md`。

**第三階段:深度。** 敵人擴張 → 多王 → 加層數。

## 驗收:要釘的後果

| 要成立的事 | 怎麼量 |
| --- | --- |
| 沒換過的魂,死了就是零 | 帶著魂死一次,讀 `souls` 和廳堂的存量 |
| 換過的,死了還在 | 同上,反過來 |
| 穿在身上的不會掉 | 現有規則,不能被改壞 |
| **刷第一層不划算** | 量「每回合換到的全域貨幣」對深度的曲線,必須單調上升 |
| 局內消耗品和局外強化共用同一個錢包 | 買了藥,可換的量就少了 |
| 練滿 = 現在的體質 | 逐項比對,不是「差不多」 |
| **練滿之前打不過** | 零強化跑機器人,通關率必須是 0——這是「零升級必須能通關」那條測試的**反面**,而它要取代它 |

最後一條要特別小心:**它推翻的是一條有理由的規則,而理由是刷。**
所以它只有在「刷第一層不划算」那條同時成立時才能通過。**兩條要一起驗,不能分開。**

## 量不到的東西

我現在所有的戰鬥數字都是在「當前體質」上量的。在新架構下那些描述的是**終局**,
還算數。但:

- **「弱體質的第 3 層難不難」** —— 機器人玩不了局外迴圈
- **「坡要多長」** —— 沒有任何現成的儀器

所以這條路走下去,**使用者的體感會從其中一個訊號變成唯一的訊號**。
那不是反對,是要先知道。

如果要補,要做的是**讓機器人能跑多場並累積強化**,而那本身是一個工具專案。
