# 王層:不生成,擺好的

> **狀態:規格,尚未實作。** 兩個未決事項在最後,兩個都會決定王的數值,所以要先答。

## 決定

**特定深度不走生成路徑。** 到了那一層,`generateLevel` 不組裝板塊,而是直接擺開一張
預先畫好的樓層:

```
        ┌──────────────┐
        │              │
        │    王 廳      │      ← 北。每個王一張,自己的地形
        │              │
        └──────┬───────┘
               │  ← 進去之後由腳本封起來
        ┌──────┴───────┐
        │   前 室  ✚   │      ← 南。到達點、爐、最後一次兌換
        └──────────────┘
               ↑
             上樓梯
```

從南邊的前室往北,進門,門封住,王登場。

## 為什麼是「擺好的」而不是「生成的」

因為**每個王要有自己的機制**,而機制要靠地形。柱子擋視線、深淵限制走位、窄口決定衝鋒
能不能成立——這些只有在**知道房間長什麼樣**的時候才設計得出來。生成的房間只能給你
「一個空的大房間」,而那就是現在的龍廳:20×20,裡面什麼都沒有。

## 現況:它已經有九成是獨立的

量過的(`DESIGN.md`):

| | |
| --- | --- |
| 龍能不能離開廳 | **不能**,0/10(80 回合每回合都在動) |
| 玩家站廳外會不會被打到 | **不會**,12/12 |
| 玩家站廳外能不能打死牠 | **不能**,三個英雄各 10 次全滅 |
| **外面的怪會不會跟進來** | **會,13/15,每次 1–2 隻** |

**只有最後一條是漏的**,而封門就是修它。所以這次改動的價值不在「隔離」——那已經幾乎
成立了——在於**確定的形狀**和**確定的進入方式**。

## 前室有一座爐,而它是全遊戲最重要的一座

爐現在是兌換所,匯率隨深度上升(第一層一成,第十層九成)。所以王廳門口那座爐是
**全遊戲匯率最好的一座**,而它就站在「進去可能死、死了整輪歸零」的那扇門前面。

> **燒了再進去,還是帶著進去賭一把?**

這個決定不用另外設計。經濟系統已經在那裡了,它只需要一座爐站在對的位置上——
而那個位置就是王廳的門口。

前室同時是**到達點**和**回復點**:你從上一層走下來就在這裡,坐爐回滿,然後決定要不要
推門。

## 封門會撞到這個遊戲的核心,而那是要付的代價

這個遊戲的設計是「你扛不住,所以要走開」,而**脫離戰鬥是被設計過的技能**:警覺會衰退,
休息要求你先甩掉追兵。

**封門等於在最需要走開的那一場拿掉走開。**

魂系就是這樣做而且成立,但它成立的前提是「你可以喝藥」。這個遊戲的回復是坐爐,而坐爐
會讓整層復活——在一個封閉的房間裡那沒有意義。

所以封門強制一條平衡條件:

> **王戰必須用你推門時身上的血、精力和藥打得完。** 沒有中途回復,沒有撤退。

這不是細節,這是決定王的血量和傷害的那條線。**畫王廳之前要先答。**

## 要做的東西

### 一、`generateLevel` 的分岔

```js
const boss = BOSS_FLOORS[depth];        // 不是 depth === DUNGEON_DEPTH
if (boss) return layOutBossFloor(depth, boss, rng);
```

一張表決定哪些深度是王層、以及各自用哪一組板塊。`DUNGEON_DEPTH` 從此不是「王在哪裡」
的答案,只是「最後一層」。

### 二、兩張板塊,每個王一組

- **前室**:小、只有兩個接口(南邊上樓梯、北邊王廳門)。含爐。
- **王廳**:每個王一張。地形是這個王的機制的一部分。

現在的 `dragonHall` 是 **20×20、八個接口、裡面完全空的**。它要重畫成一個接口(南),
而且要有東西在裡面。

### 三、封門

**現在沒有可上鎖的門磚。** `DOOR_CLOSED` / `DOOR_OPEN` / `DOOR_BROKEN`,沒有鎖。

兩條路:

- 新增 `T.DOOR_SEALED`(不可走、不透光),進門的腳本把門換成它
- 或者不動地磚,只加一條規則:王還活著的時候,那一格不能走

我傾向**第一種**。它看得見——玩家看到門變成別的東西,就知道發生了什麼——而第二種是
一條隱形的規則,玩家只會覺得自己卡住了。

### 四、登場演出

`fx` 和 `anim.js` 的階段機制已經夠用,不需要新架構。要的是一個腳本:門關上、鏡頭停一下、
王的名字和血條出現、第一次宣告。

### 五、滿版血條

**完全沒有這個東西。** 要新的 UI 元件:王的名字 + 一條橫跨畫面的血條。

## 未決:兩件,都會決定王的數值

**一、王戰真的不能回復嗎?**

如果是,王的數值要照「玩家帶著滿血和三瓶藥進來」設計。
如果不是(例如廳裡有一座只能用一次的爐),那是完全不同的一張表。

**二、血條蓋住什麼?**

畫面頂端現在是訊息列。滿版血條要嘛蓋掉它,要嘛把它推下去、地圖縮一點。
在 440 寬的框裡,地圖是正方形而且已經是最大的東西,所以這個取捨是真的。

## 還沒排進來的

**多王需要更多敵人。** 現在 11 種,最深的新敵人在第 7 層,第 8～10 層沒有任何新東西。
一個王層之後接著更深的樓層,而那些樓層現在沒有東西可以放。

**所以順序是:敵人擴張 → 王廳與多王 → 加層數。** 這份規格描述的是中間那一段。
