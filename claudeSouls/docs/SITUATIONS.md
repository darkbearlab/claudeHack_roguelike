# 情境池:怎麼描述一個你想要的空間

> 這份文件是**給人寫規格用的**,不是描述已完成的功能。情境系統還沒做。
> 先寫下來是因為格式本身就是設計的一部分——用錯的方式描述,會做出錯的東西。

## 為什麼不能只講形狀

房間形狀的池子只能生出幾何,生不出情境。這三個例子沒有一個是純幾何:

| 想要的 | 幾何 | 但還需要 |
| --- | --- | --- |
| 空曠但中間有特殊地形 | 大空間 + 中央物件 | 敵人**散開**,那個物件才變成必須繞的東西 |
| 列柱大廳 | 兩排柱子 | 柱子要**擋視線**,而且遠程要**站在柱後** |
| 開放空間裡的窄路 | 一條可走的線 | 兩側的「牆」是**威脅**不是石頭 |

第三個最能說明問題:**那條走廊是用危險畫出來的,不是用石頭。** 地形生成器再怎麼換
池子都生不出它,因為它有一半是敵人。

所以要的是**情境模板**:一塊幾何 **+ 它自己的選角指令**。

### 這個模式已經存在,只是只有一個

`placeStoreroom` 放寶箱,`placeGuards` 用 `GUARD_FOR` 挑一隻**和戰利品相配**的守衛,
放在寶箱和房間出口**之間**,而且**一開始就是清醒的**。幾何、道具、敵人種類、位置、
狀態,全部一起決定——那就是一個情境模板。情境池是把它推廣。

## 描述一個情境,要講五件事

```
1. 決定      玩家在這裡被逼著選什麼?
2. 空間      大概多大、裡面有什麼
3. 誰在裡面  用角色講,以及站哪(相對位置)
4. 出現在哪  深度、主題
5. 做錯會怎樣
```

### 1. 決定 —— 最重要的一條

**其他四條都是為這一條服務的。** 只講「兩排柱子的大廳」,會得到一個有兩排柱子的
大廳、敵人隨機灑在裡面——那什麼都不是。

要講的是它逼出什麼選擇:

- 列柱大廳 → **「我走哪條走道」**,而且走進去就看不見另一條
- 威脅構成的窄路 → **「衝過去吃箭,還是繞遠路花回合」**
- 空曠 + 中央地形 → **「要不要用那個東西當掩體」**,用了就被逼到一邊

這一句會變成模板的 `intent` 欄位,進文件,而且**是驗收標準**。

### 2. 空間

大小範圍就好,不用精確。「一條 8–12 格的路徑,兩側各留 3–5 格」這種程度剛好。

裡面有什麼要講清楚,因為地形的效果差很多:

| 地形 | 擋移動 | 擋視線 | 擋投射物 |
| --- | --- | --- | --- |
| 牆 | ✓ | ✓ | ✓ |
| 柱子(**還沒有,列柱大廳的先決條件**) | ✓ | ✓ | ✓ |
| 瓦礫 `RUBBLE` | ✓ | ✗ | ✗ |
| 坑 `PIT` | ✓ | ✗ | ✗ |

現有的掩體是**隨機灑的**(每房 0–3 塊),所以「兩排柱子」這種有意圖的排列現在生不出來。

### 3. 誰在裡面 —— 用角色,不要用種類

敵人表會變,而且同一個情境在第 3 層和第 9 層該放不同的東西。講角色,讓深度去挑:

- **遠程** —— 隔著空地施壓
- **擋路的** —— 慢、耐打,佔住路
- **會衝的** —— 會縮短距離,懲罰站著不動
- **守衛** —— 不追,守著一個點,一開始就清醒

位置用**相對名字**講:`柱子後面`、`路徑對面`、`房間外圍`、`出口和寶箱之間`。
這些會變成模板裡的**錨點**,所以你講的位置會直接變成資料,不是我猜的。

### 4. 出現在哪

深度範圍,以及主題(主題系統還沒有,但情境池會照主題分)。

### 5. 做錯會怎樣

這條是用來檢查**威脅是不是真的**。如果「做錯」的後果講不出來,那個情境大概只是
裝飾。「直線走 = 每回合吃一發;停在路徑中間 = 兩邊一起打你」——這種程度就夠。

## 完整範例

拿上面第三個情境:

```
決定    直線衝過去吃兩側的箭,還是繞遠路多花五六個回合
空間    一條 8-12 格的可走路徑,兩側各留 3-5 格開闊地
誰      兩側各 1-2 個遠程,一開始就清醒,站在射得到路徑的位置
        路徑盡頭 1 個擋路的
出現    第 4 層以後
做錯    直線走 = 每回合吃一發;停在路徑中間 = 兩邊一起打你
```

## 為什麼這個格式值得遵守:每一條都能變成測試

這個專案的紀律是**釘後果,不釘機制**。上面那個規格可以直接寫成:

- 路徑上**每一格**是不是都被至少一個遠程敵人涵蓋?不是的話它只是一條普通走廊。
- 繞遠路是不是**真的**存在,而且真的比較久?不是的話那不是選擇,是懲罰。
- 玩家進場的位置看得到威脅嗎?看不到就不是決定,是埋伏。

**一個生不出這些性質的情境,就是沒有做到規格**,而那是可以自動檢查的——跟現在
「篝火房不生怪」「boss 一定放得下」是同一種測試。

# 未來:地形互動(還沒做,已排在 2 格寬走廊和門之後)

構想是把地形從「能不能走」擴充成「走上去會怎樣」:

- 推進**深淵/坑** → 直接墜落死亡
- 推到**火/尖刺** → 吃傷害
- 推到**困難地形** → 移動變慢(例如走一格要兩回合)
- **毒地形**、**沼澤**(毒 + 困難)
- 推**撞牆** → 吃傷害

`TILE` 的定義本來就吃一個 extras 物件(`door`、`pit`、`bonfire`、`chasm`、`bridge`
都是這樣掛的),所以掛效果不需要改結構。

## 動手前必須先解決的四件事

**一、擊退目前是單向的,這是最大的問題。**
查過了:**沒有任何敵人的攻擊有擊退**,只有玩家有(`chop`、`shove`、詞條)。所以
「推進深淵就死」照現狀做出來會是**純粹的玩家武器**——你可以把一整層推下去,而它們
永遠不能這樣對你。

> 要嘛先給某些敵人擊退(讓地形變成雙向的威脅),要嘛接受這是一個玩家專屬的處決手段
> 並照那樣定價。**不能不決定就做。**

**二、`knockBack` 現在會在不可走的地形前停下。**
`if (!this.level.passable(nx, ny, e)) break;` —— 所以現在**推不進深淵**。要讓它變成
死亡,得刻意開一個「可以被推進去、但不能走進去」的例外。那個例外要小心寫,不然
會變成「敵人自己走進深淵」。

**三、預告契約適用於墜落。**
被推下去而死是一次「攻擊」,所以它必須**看得出來**:玩家要能事先知道自己背後是深淵,
而且要知道那一擊會擊退。這大概表示擊退攻擊的預告要畫出**被推到哪裡**,而不只是
畫出打到哪裡。

**四、困難地形會碰到能量排程器。**
移動變慢在這個引擎裡是自然的(敵人本來就有 speed/energy),但這個專案有一個
反覆出現的 bug:**被拒絕但不推進回合的動作會變成無限迴圈**(篝火、收招、走進 NPC、
機器人撞牛頭人)。「這一步要花兩回合」如果實作成「第一次嘗試被拒絕」,就是同一個
陷阱的第五次。

## 一個會被連帶重估的東西

`shove` 現在的定位是「幾乎沒有傷害——它是用來移動東西的」,而 falchion 的價值有一半
在這裡。**一旦地形會殺人,shove 就變成處決技**,那把武器要重新定價。
