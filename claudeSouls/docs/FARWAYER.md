# 巡禮者:規格

> **狀態:已實作,但目前停用(`wip`)。** 上半部是原始規格,原文保留;中段〈實作紀錄〉是做完之後
> **被量測推翻或修正的地方**。
>
> 短版:**骨架全對,數字幾乎全錯**,而且錯得有跡可循——既有的測試自己抓到兩條,
> 一根木樁抓到第三條,一個名字撞車讓整套機制靜靜地什麼都沒做。

## 她是誰

精靈的巡禮者(farwayer)。銀色長髮姬切頭,黑色羽毛的披風。

名字和機制對得上,而且這不是裝飾:**巡禮者沿路留下記號。印記就是她走過的路。**

## 一句話

**她的每一回合是兩拍。三招各有兩拍、共六拍,每一拍有自己的形狀,並在命中的敵人身上留下印記。
同一個印記蓋到第二次時,整組印記被吃掉並發動效果——而當時身上混了幾個別的印記,效果就放大幾倍。**

## 拍:她的回合結構

這是整份規格裡唯一動到引擎的地方,所以先講清楚它的一般形式。

現在 `advancesTurn` 是個布林值,而且全遊戲**只有翻滾是 `false`**。把它換成**拍的花費**,
再讓英雄宣告一個回合有幾拍:

| | 一回合的拍數 | 攻擊 | 翻滾 | 走路 |
| --- | --- | --- | --- | --- |
| 老騎士 / 攝魂師 / 執旗侍從 | 1 | 1 拍 | **0 拍** | 結束回合 |
| **巡禮者** | **2** | 1 拍 | **1 拍** | 結束回合 |

**現有三個英雄的行為必須逐位元不變**,而上表就是今天的規則換一種寫法:一回合一拍、
攻擊用掉它、翻滾不用拍(所以「翻滾不推進回合」)、翻滾一回合一次的限制照舊。
這條是驗收項目,不是註解。

### 走路會斷句,翻滾不會

這是她的核心手感,而且兩者**刻意不同價**:

| 動作 | 代價 | 句子 |
| --- | --- | --- |
| 攻擊 | 一拍 | 繼續 |
| 翻滾 | 一拍 | **繼續** |
| 走路 | **整個回合** | **斷掉** |

如果走路也只是一拍,她一回合能走兩格,而全遊戲的間距數學(前搖判讀、衝撞距離、
狗的節奏)都是照玩家一回合一格算的。所以走路必須維持「一回合一格」。

分開定價之後長出一個很好的東西:**翻滾是她的腳步,走路是她的失敗。**
被逼到要用走的,你就輸掉了整句話。

她的耐力消耗低、恢復快,所以**限制她的不是耐力,是拍。**
真正咬人的是中途被迫閃避——那一拍沒有留下印記,而印記的時限還在走。

## 印記:成對即引爆

一隻敵人身上帶著一組印記(同一種印記不會有兩個,因為第二個會立刻引爆)。

```
施加印記 M 到目標身上:
  目標身上已經有 M ?
    ├─ 有  → 引爆:發動 M 的效果,倍率 = 1 + (身上其他印記的數量)
    │        然後【整組印記清空】
    └─ 沒有 → M 貼上去,五回合後自然消失
```

- **倍率只放大強度,不改變效果的種類。** 五種印記 × 0～4 個混合 = 25 格的對照表,
  那是查表遊戲。玩家要學的是五個效果加一條規則。
- 五種印記,所以引爆時最多帶**四個**其他印記,倍率上限 **×5**。
- **形狀打到誰就印誰。** 招式的形狀本來就決定命中範圍,印記跟著走。
  打狗群是同時鋪好幾組、先湊滿哪組先炸哪組;打王是一次大的。同一套系統,兩種質地。

### 五回合這個數字是對的

要吃到滿倍率需要六次施印,一回合兩拍 ⇒ **最少三回合**:

| 回合 | 第一拍 | 第二拍 | 目標身上 |
| --- | --- | --- | --- |
| 1 | 二招 → B | 二招 → C | B C |
| 2 | 三招 → D | 三招 → E | B C D E |
| 3 | 普攻 → A | 普攻 → A | 引爆 A,帶四個其他 → ×5 |

第一回合下的 B 在第三回合還活著(過了兩回合),**剛好夠,而且只夠**。
中間只要有一回合被迫閃避,你就開始賠時間。

## 六拍五印

| 招 | 第一拍 | 第二拍 |
| --- | --- | --- |
| **一招(普攻)** | A | **A** |
| 二招 | B | C |
| 三招 | D | E |

一招兩拍同印,所以**普攻是引信**:一回合連打兩下普攻必定引爆。
你用二招三招鋪陳,用普攻收。而如果你只會打普攻,那就是「很普通的追加傷害」,
保底也在同一條規則裡。

**拍是「這回合的第幾個動作」,不是「招式自己的第幾段」。** 第一拍用普攻、
第二拍用二招,吃到的是二招的**第二拍**版本(C)。這條是整個系統最承重的規則。

## 五個效果

| 印 | 來源 | 效果 | 倍率作用在 |
| --- | --- | --- | --- |
| **A** | 一招兩拍 | 追加傷害 | 傷害值 |
| **B** | 二招第一拍 | 易傷:受到的傷害提高,持續數回合 | 提高的幅度 |
| **C** | 二招第二拍 | **回血** | 回血量 |
| **D** | 三招第一拍 | **擊退 + 失衡** | 擊退格數與失衡值 |
| **E** | 三招第二拍 | **存下額外的拍** | 存下幾拍 |

### 為什麼強的效果掛在第二拍,但是「玩家側」的效果

原本的想法是「第二拍難,所以效果比較強」。前半對,後半會**倒過來**。

第二拍難,是因為**被壓著打的時候你會拿第二拍去翻滾**。所以實際結果是:
順風時你輕鬆吃到第二拍,逆風時你永遠只拿得到第一拍。
強效果掛在第二拍 ⇒ **她順風時最強、逆風時最弱**,而那是反的。

所以效果**依拍分邊**,不依強弱:

- **第一拍(B、D)= 敵人側**。逆風也拿得到的,拿來續命。
- **第二拍(C、E)= 玩家側**。「明明該閃卻選擇唱完」換到的是**讓你能繼續貪的資源**。

這樣第二拍在逆風時**更值得賭**,不是更沒用。強度仍然可以比第一拍高,只是強在別的軸上。

### D 為什麼是擊退而不是暈眩

因為現有的機制不支援後者,而**倍率必須有一個能線性放大的東西**。

`stagger()` 只在目標處於 `WINDUP` 時有作用(`if (this.state !== STATE.WINDUP) return false`),
而且效果是**把前搖延後一回合**,不是暈眩。所以「失衡 ×5」對一個沒在前搖的敵人是完全的零。
而「暈眩 ×5 回合」則是直接殺死那隻怪。兩邊都不能當倍率的載體。

**擊退格數可以。** 1 到 5 格,線性,對前搖中和沒前搖的目標都成立。
而且它順便解開一件卡住的事:地形互動(推進深淵之類)一直卡在**沒有任何東西有擊退**。
她會是第一個。

失衡照舊一起給,只是它不是倍率的主軸。

## 數值(全部暫定,要量)

```
stamina: { max: 10, regen: 5 }      // 低上限、極快恢復:限制她的是拍不是耐力
roll:    { cost: 3, distance: 2 }   // 真正的代價是那一拍
family:  'paired'                    // 雙刃 —— 兩把刀,兩拍。武器就是機制
```

六拍的耐力各自都低(暫定 2～4),形狀暫定:

| 拍 | 形狀 | 說明 |
| --- | --- | --- |
| 一招 1 | `front` | 起手 |
| 一招 2 | `arc3` | 回刀,順便照顧狗群 |
| 二招 1 | `reach2` | 踏進去 |
| 二招 2 | `line3` | 更深 |
| 三招 1 | `around` | 轉身,八格 |
| 三招 2 | `behind` | **背後那一格** |

最後一格是這套 kit 裡最大膽的一條:**最強的自我增益要求你背後有東西。**
被包夾才拿得到的獎勵,對一個舞者角色是對的。但它也可能根本吃不到,
所以它是第一個要量的東西。

回血基準 1 點(玩家 `hpMax` 是 12),滿倍率 5 點。
存拍基準 1 拍,滿倍率 5 拍——這個上限我最不放心,很可能要砍。

## 它明確**不做**的事

- **AI 不讀印記。** 和雜訊層同一條紀律:這是玩家側的資訊,沒有任何規則反過來查它。
- **不做「額外效果」,只做倍率。**
- **不為她改敵人。** 她面對狗群比較弱,那就是她的弱點。
  兩拍普攻約等於別人一回合殺一隻,**回合經濟上其實沒差**,差的是印記被浪費掉。
- **不做跨回合的拍數殘留。** 每回合從第一拍開始。存拍(E)是唯一的例外,而且是明講的資源。
- **不特別處理存檔。** 樓層本來就從種子重建,坐火會清掉所有印記。

## 陷阱

**一、「什麼算是她的普通攻擊」。**
這個專案已經在這題上錯了**四次**(`step()` 寫死 `strike`、機器人只帶長劍、
機器人的 `arms()` 讀裝備、`meleeSkill()` 偏好武器的 primary)。她是第一個讓這個答案
**有後果**的角色。

好消息是路徑已經是對的:方向鍵撞擊走 `game.js` 的 `useSkill(swing, {dx,dy})`。
所以規則是——**拍的狀態機放在 `useSkill` 裡,撞擊就自動繼承**。
放在別的地方就是第五次。

**二、被拒絕但不推進回合的動作是無限迴圈。**
已經犯過五次(篝火、收招、走進 NPC、機器人撞牛頭人、翻滾)。
她新增了一個:**第一拍因為耐力不足被拒絕時,回合推進了嗎?**
必須明確定義,而且要有測試,不能靠「應該沒事」。

**三、機器人的策略假設一回合一個動作。**
在改機器人之前,她的**所有**數值測量都是垃圾。這件事要排在調數值之前,
不是之後。這個專案已經三次把機器人的策略錯誤當成平衡問題。

**四、`advancesTurn` → 拍花費是一次重構,而重構要證明自己什麼都沒改。**
現有三個英雄的行為必須逐位元相同。

## 驗收:要釘的後果

照紀律——**釘後果,不釘機制**,而且每一條都要驗「把規則關掉會不會失敗」。

| 要成立的事 | 怎麼量 |
| --- | --- |
| 重構沒有改到現有英雄 | 三個英雄各跑固定種子的機器人,逐步序列與改動前相同 |
| 她一回合真的是兩拍 | 兩次攻擊之間敵人沒有行動過 |
| 走路會斷句 | 第一拍後走一步,第二拍不存在 |
| 翻滾不會斷句 | 第一拍後翻滾,回合結束;第一拍後翻滾**不是**第二拍的攻擊 |
| 翻滾一回合仍然只有一次 | 兩拍都翻滾會被拒絕 |
| 同印第二次會引爆並清空整組 | 直接讀敵人身上的印記 |
| 倍率 = 1 + 其他印記數 | 鋪 0～4 個其他印記,量五次效果值 |
| 印記五回合會消失 | 貼上後等六回合 |
| 形狀打到幾隻就印幾隻 | 用 `arc3` 打三隻,三隻都有 |
| 撞擊 = 一招 | 撞擊之後,那隻身上有 A |
| **撞擊會消耗一拍** | 撞兩下 = 引爆,而且回合推進了 |
| AI 沒有讀印記 | 把印記全部清成空的,敵人的行為序列不變 |
| 她打得贏,而且不是靠秒殺 | 機器人 `failures: 0`,且她的擊殺平均耗拍數 > 2 |
| `behind` 那一拍吃得到 | 統計它在一次跑完的樓層裡實際命中幾次。**如果接近零就是設計失敗** |

## 還沒決定的

- **存拍(E)的上限。** ×5 存五拍很可能太多。這是最可能要砍的數字。
- **B 的易傷持續幾回合**,以及它和倍率的關係(倍率放大幅度,不放大時間——但時間也要有個值)。
- **六拍的形狀**,尤其 `behind`。上表是起點不是結論。
- **她的護甲家族與起始裝備**。`paired` 這個家族要新增,而武器家族是嚴格不互通的,
  所以要一整條階梯,不是一把刀。
- **耐力 10 / 恢復 5 會不會直接讓耐力這條軸在她身上消失。** 如果消失了,
  那她的難度必須明確地來自別的地方(血量、距離、形狀的位置要求),
  而不是「反正她比較簡單」。

# 實作紀錄

以下是照這份規格做完之後,**被量測推翻或修正的地方**。規格是對的骨架,數字幾乎全錯。

## 一個名字撞掉了整套機制

`beat` 是透過一個 getter 讀的,而我把它取名叫 `face`——**同一個 class 上已經有一個
`face(dx, dy)` 方法**(轉向)。方法贏了,`p.face` 是個函式,`beat >= 1` 永遠是 false。

結果:**她的六拍每一拍都放出第一面。** 形狀對、價格對、印記對,只是永遠是兩面裡的
錯的那一面。沒有任何東西丟出例外,而且**當時 160 條測試全過**——因為沒有一條測試問過
「第二拍做了什麼」。

抓到它的是一個手寫探針,不是測試:對著木樁打完一句,印記卻在第二拍就被清空了。
往回推是傷害值 2 而不是 3,再往回推是價格 3 而不是 4。

現在有兩條測試釘這件事,而且都驗過:把 getter 改成永遠回 0,兩條都掛。

## 數值:規格猜的幾乎全錯,而現有的規則自己抓到了

規格寫 `stamina 10/5`、`roll 3`。**她一存在,兩條既有測試就在一分鐘內拒絕了它:**

| 測試 | 它說了什麼 |
| --- | --- |
| 「沒有人可以永遠迴避」 | 翻滾 3 對上回復 5 ⇒ **翻滾會回血**,遊戲裡沒有任何前搖對她有意義。和老騎士當年 4 對 4 是同一個 bug |
| 「收招是規則定價的,不是手感」 | 回復 5 的時候,3 點的八格橫掃是**零回合的承諾** |

修法是**順著設計而不是逆著**:她的攻擊維持便宜,**翻滾變成全遊戲最貴的**(7)。
規格自己就說「咬人的是被迫移動和閃避」,所以貴的應該是閃避。

## 她少了一顆引擎,而木樁才問得出來

機器人問不出這件事:量過 8 次跑,它扮老騎士**揮了 83 次、翻滾了 9,108 次**。
它的策略是「幾乎不計代價避免受傷」,那是「完美閃避者活不活得下來」的好儀器,
對「一個回合值多少」則完全無用。

所以做了 `tools/dps.mjs`:一根木樁、滿條、能付得起就揮,付不起就等。它立刻指出:

> **她的句子是六拍、18 點精力、三個回合,而那三個回合全都是攻擊回合——攻擊回合的回復是
> 零(見 `EFFORT`)。她連一次都唱不完。**

所以加了 `REFUND_PER_EXTRA`:**引爆時,每一個「多出來的」印記退還 4 點精力。**
注意乘的是 `mult - 1` 而不是 `mult`——**沒有伴的引爆什麼都不給**。

這條同時解掉引擎和退化打法:普攻兩拍同印,所以連打普攻必定以 ×1 收尾,
永遠拿不到退還。**設計自己的主張變成了讓她活下去的東西。**

## 普攻從 2 漲到 3,因為懶惰的打法本來是最強的

裝上退還之後掃了一次網格:普攻價格 × 印記傷害,各三檔,量 24 回合的總傷害。

| 普攻價 | 一直打普攻 | 唱句子 | |
| --- | --- | --- | --- |
| **2** | **56** | 51 | ← 懶惰的打法贏 |
| 3 | 35 | 51 | |
| 4 | 28 | 49 | |

價格 2 的時候她的普攻是 **1.75 傷害/精力**,接近老騎士的三倍。改成 3 之後**句子的傷害
幾乎沒動**(靠退還撐著),只有重複被打下去。那正是這個角色要的形狀。

## `behind` 的答案:規格擔心的事是真的

規格把「三招第二拍打身後」列為第一個要量的東西,說「如果接近零就是設計失敗」。

量出來:**單一目標的情況下,包含 `return` 的六拍句子比四拍的短句還差**
(47 對 131,而一直打普攻是 63)。因為背後沒東西的時候那一拍完全落空。

**她最好的一句是四拍兩回合**:`reach` 兩拍鋪兩個印,普攻兩拍收成 ×3。
`return` 是情境牌,不是常規輪替。

這沒有立刻改掉,因為它其實是個有意思的決策空間,而不是壞掉的東西。記在這裡而不是
當場調數值。

## 機器人本來被禁止扮演她

`act()` 的保留量規則是「脆皮就留兩次翻滾的量」。她翻滾 7、上限 16(當時),
**於是留 14 剩 2**,而她的一個回合要花兩拍。8 次跑裡她揮了 710 次、翻滾了 25,562 次
——機器人不是把她打壞,是**根本不被允許打**。

改成:保留量不得超過「這個回合本身要花的錢」,寫成 `staminaMax - cheapest * beats`。
**對三個一拍英雄是逐位元相同的**(7、4、5 還是 7、4、5)。

## 大廳裡的按鈕在說謊

大廳沒有時鐘,`worldTurn()` 提早 return——而那正是 `tick()` 重置拍數的地方。
走一步會 `endPhrase()`,於是拍數停在 `beats`,**大廳裡每一顆技能鈕都畫著第二面**:
錯的形狀、錯的價格,而大廳唯一的工作就是告訴你這個角色會做什麼。

這是在瀏覽器裡看到的,不是測出來的。修法是 `newPhrase()`,大廳那一支也呼叫它。

## 還沒量到的

**機器人不打架,所以印記在真實戰鬥裡的表現是未知的。** 它扮所有英雄都是這樣
(老騎士 8 次跑只揮 83 下,等待佔 86% 的回合),所以這不是她帶來的問題,
但它確實讓「她在真的會還手的東西面前唱不唱得完一句」變成一個**沒有答案的問題**。

木樁量得到「一個回合值多少」,量不到「被追著跑的時候還剩幾拍」。
那是下一個要做的儀器,而它比再調一次數字重要。

## 最後的數字

```
stamina: { max: 20, regen: 4 }     roll: { cost: 7, distance: 2 }     beats: 2
pace   3 / 3    front  → arc3      step  / step
reach  3 / 4    reach2 → line3     thorn / spring
return 4 / 3    around → behind    gale  / ember
印記持續 5 回合 · 引爆退還 4 × (倍率-1) · 存拍上限 2
```

木樁上,單一目標,每回合傷害:老騎士 1.10、**巡禮者 1.27**、執旗侍從 0.40、攝魂師 0.20。

# 停用中:重新設計的規格

> **狀態:`wip: true`,不可選。** 大廳不會站她,標題畫面把她列出來但是灰的、標「未完成」。
> 她仍然在 `HEROES` 裡,所以每一條規則和每一條測試照樣管她——**把一個角色從遊戲裡拿掉
> 的同時也從測試裡拿掉,他回來的時候會是爛的。**

## 為什麼停,以及不是為什麼停

**不是因為她壞了。** 數字是誠實的:木樁上單體每回合 1.27(老騎士 1.10),
她的句子打贏一直按普攻是 131 對 63,171 條測試全過,機器人 20 次跑 0 failures。

停的原因是**形狀還在審查中**,而審查的觸發是兩件事:

1. 使用者的判斷:「我覺得怪怪的」。這是設計判斷,我沒有它的內容,所以它是這份規格
   最上面的未決事項,不是我可以自己填掉的空格。
2. **前後搖重構會改變問題本身。** 見下。

## 量出來確實不對勁的三件事

這些是我能舉證的,不是猜的:

**一、`return` 不在常規輪替裡。**
規格自己把「三招第二拍打身後」列為第一個要量的東西,說接近零就是設計失敗。量出來:
單體時,含 `return` 的六拍句子 **47 傷害**,四拍的短句 **131**,一直按普攻 **63**。
她最好的一句是 `reach reach pace pace`——**三招裡有一招基本上不進輪替**。

**二、兩個「存起來的資源」是多了一個。**
`ember`(存拍)上限被我壓在 2,而且規格裡我自己就標記它是最不放心的數字。
如果大招要進來,它和存拍搶同一個位置。

**三、五個印記裡有四個的效果幾乎不會發動。**
句子的打法是鋪四個印、用普攻收——所以引爆的永遠是 `step`,另外四個印**只當乘數,
它們自己的效果從來沒發生過**。易傷、回血、擊退、存拍寫在資料裡,實際上是四個數字 +1。

這第三點我覺得是「怪怪的」最可能的來源:**她看起來有五種效果,實際上在打一種。**

## 前後搖重構改變了什麼問題

兩拍的存在理由之一是「她的回合結構和別人不同」。但如果前後搖變成**每個動作明碼標價、
畫在頭上**,那「回合結構」本來就會變成全遊戲都看得見的東西——她的差異可能不需要用
一套獨立的機制來表達。

同時,重構會讓一個**目前不可能的效果**變成可能而且好讀:

> **無視失衡值的 +1 前搖。**

現在 `stagger()` 只在 `WINDUP` 狀態有效,而且要先打破失衡才 `timer++`。所以「延後一擊」
是被失衡值把關的,對 2×2 完全無效——老騎士的招牌「卸勢」推不動它們,那是他的形狀。
**一個無視失衡的 +1 前搖是現在沒有任何東西做得到的動詞。**

而且它在新的顯示下是**一眼可讀的**:所有人頭上多一顆空心點。

## 三個候選方向(未定)

| | 保留 | 拿掉 | 新增 |
| --- | --- | --- | --- |
| **A. 現狀 + 大招** | 兩拍、印記 | `ember` | 魔法欄放「儲存式緩速」大招,唱完句子充能 |
| **B. 只留大招** | — | 兩拍、印記 | 同上,她變成一般回合結構 + 一個很強的招 |
| **C. 現狀 + 收斂印記** | 兩拍 | 五印減成三印 | 讓每個印都有機會真的引爆 |

我的傾向是 **A**,理由是兩拍是這個遊戲裡唯一「玩家自己的排序就是技術」的地方,
而 B 把她變成被動角色——**+1 前搖不給你任何要做的事**。但 C 才是直接治「五個印在打一種」
那個病的,所以 A 和 C 可能要一起做。

**這一格由使用者填。**

## 大招的規格草案(如果走 A 或 B)

只寫已經確定的部分:

- **位置:魔法欄。** 她的 `kit.magic` 是 `null`,那顆按鈕已經接好線、目前是個有名字的洞。
  攝魂師也是空的,老騎士也是,侍從有 `rally`——所以有前例。
- **充能靠打,不靠火。** `charges` 系統存在但是坐火補滿。她的要改成**唱完一句才充**,
  這樣整條線接起來:拍 → 印記 → 唱完一句 → 充能 → 大招。
- **無視失衡值。** 不走 `stagger()`,直接 `timer++`。這是它存在的理由。
- **會延長進行中的前搖。** 紅格已經亮了,你放招,它多掛一回合——那是這招的畫面。
  `stagger` 本來就會延長進行中的前搖(只是要先破失衡),所以這是同一件事去掉關卡。
- **拖的是刀,不是腳。** 只加前搖,**不動移動速度**。遊戲裡每一個距離數字都是照
  「玩家一回合一格」算的,動了速度整個間距數學會歪——和「走路必須吃掉整個回合」同一個理由。

### 還沒決定的

- 範圍(自身周圍幾格?全場?)
- 充能需要幾句、能存幾發
- 對王有沒有折扣或免疫
- **要不要同時給玩家自己 -1 前搖**,那會是完全不同的一張牌(進攻 vs 防守)

## 解除停用的條件

1. 上面那格填了(A / B / C)。
2. 前後搖重構的第一階段做完——因為 +1 前搖在「前搖看不見」的遊戲裡是不可讀的。
3. 她的測試照舊全過,而且新增「五個印記各自都會被引爆」這條後果的量測。
