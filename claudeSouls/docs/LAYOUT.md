# 樓層排法:填滿 vs 一本道

> **狀態:`route` 是預設。** 舊的填滿模式還在,用 `?layout=fill` 進入。
>
> 兩種都跑得過完整測試(178 條),所以退回去是一個網址參數,不是一次回滾。

## 為什麼要改

量出來的問題:

| | |
| --- | --- |
| 上樓梯走到下樓梯 | **53 格** |
| 那條路經過幾塊板塊 | **5.5 塊** |
| 一層有幾塊 | 16.4 塊 |
| 帶自己守軍的板塊 | **6.6%** |

**地圖比穿過它的路徑大三倍,而多出來的三分之二是空的。**

## 改法比想像中小:同一個組裝器,叫它用走的

`assemble` 的成長迴圈從 frontier **隨機**抽一個 socket 來長。那正是樓層會往四面八方攤開的原因——任何一個開口都同樣可能是下一個。

改成抽**最後一個**,同一段程式就變成深度優先,自己走成一條鏈:

```js
const idx = routing ? frontier.length - 1 : rng.rn2(frontier.length);
```

整個差別就是這一行。再加一個板塊數上限、一個死路口袋,route 模式就成立了。

所以這不是第二套組裝器,是一個旗標——**也就是說退回去只要一個常數**,而且兩種可以在同一個 build 裡互相比較。

## 量到的

| | fill(現在) | route + 40×30 |
| --- | --- | --- |
| 板塊 | 14.9 | **6.4** |
| 可走格 | 799 | **368** |
| 到樓梯 | 54 | **39** |
| 敵人 | 10.7 | 9.4 |
| **每敵人分到的地** | 75 格 | **39 格** |

**路程少 28%,密度加倍,敵人數幾乎沒動。**

地圖尺寸跟著排法走(`MAP_FOR`):填滿要地方攤,一本道不用。60×30 上放六塊會讓三分之二的地圖是沒挖的岩石——那不會壞,但浪費鏡頭和小地圖。

## 過程中抓到一個舊 bug

route 模式第一次跑出來是 **18 塊**,不是 6 塊。追下去發現可達性那一關:

```js
for (let pass = 0; pass < 20; pass++) {   // 沒有「已經全部可達」的出口
```

它跑滿二十輪,每輪不是開門就是**長一塊新板塊去接沒被走到的地**——而它從來沒問過「有沒有沒被走到的地」。

填滿模式下這是隱形的:格子本來就滿了,沒地方長,所以那二十輪等於什麼都沒做。一旦格子有空,它就把六塊的路線長回十八塊。

現在加了 `anyUnreached(seen)` 的出口。**這條修正對兩種排法都是對的**,不是 route 專用。

## 扶正之前要補的六個下限

route 一開始掛五條、加上新板塊之後掛七條,全部是同一件事:**六塊的樓層沒辦法保證十六塊
靠數量堆出來的東西。** 補法都在 `populate.js`,而且每一條都是「不要安靜地失敗」:

| 掛掉的 | 為什麼 | 補法 |
| --- | --- | --- |
| 有樓層一慢一快缺一半 | 房間都被守軍占了,`roomsOnly` 找不到位置 | 最後手段:走廊也可以站,但不能在火旁邊 |
| 有樓層 0～2 隻敵人 | 同上,遊蕩填充是**位置**用完不是預算用完 | 樓層下限三隻 |
| 菁英只出現在 35 層裡的 24 層 | 同上 | 菁英也給最後手段——「每層一隻」是承諾 |
| 王層的接近路是空的 | 龍廳是 2×2,route 尺寸的格子放不下護衛和火 | **王層維持 fill 的地圖尺寸**(它本來就是手工擺的) |
| 雙開門數量不足 | 門檻是照「每層」算的 | 改成**照板塊算**:六塊的樓層本來就只有十六塊的三分之一 |
| 窄門取樣不足 | 同上,取樣量縮水 | 門檻跟著縮 |

最後兩條要說清楚:**那是統計量的分母變了,不是門變少了。** 一個因為樣本縮水而失敗的統計
量測的是樣本。改成「每塊 0.5 扇」有推導:兩塊之間最多一扇門,箭頭和開放邊緣不生門,
而 `doorAt` 有四分之一機率留成單純的缺口——實測 0.67。

## 還沒做的

1. **抽牌不放回 + 組成下限。** 上面那五條測試就是驗收條件。
2. **每塊板塊都帶敵人。** 22 張裡只有 3 張有。注意這**不會讓敵人變多**——`stageTiles` 從同一個預算扣——所以它治的是分布,不是數量。
3. **板塊縮到 8×8。** 固定路程下邊長越小 = 板塊越多 = 多樣性越高。下限是 `line6`(6 格)和 2×2 的身體,所以 8(內部 6×6)是底。
