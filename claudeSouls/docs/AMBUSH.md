# 伏擊:規格

> 這份文件是**寫給還沒實作的東西**的,和 `SITUATIONS.md` 一樣。
> 先寫下來是因為這個機制有幾個地方一不小心就會變成 bug 而不是機制。

## 它要解決什麼

上一輪把精力變稀缺之後,留下一個洞:**站著不動現在是最好的回復手段,而站著不動不痛。**
量出來老騎士有 77.7% 的戰鬥回合在等待。前期敵人打你要 6–8 下,退到走廊喘一口氣沒有代價。

伏擊的工作是讓**移動和停留有代價**。它不是為了增加傷害,是為了讓「往回走」和「站著等」
不再免費。

## 兩個特徵,不是一個

這是整份規格的重點。伏擊點**自己完全不反應**,它們只聽信號點的。

| | 信號點 signal | 伏擊點 nest |
| --- | --- | --- |
| 是什麼 | 一塊看不見的感測區 | 一組看不見的出生格 |
| 觸發條件 | 玩家走進 **5 格**內 | **沒有**。只被信號點喚醒 |
| 作用 | 喚醒 **10 格**內的所有伏擊點 | 生出裡面的東西 |
| 每個種子 | 有些不生效 | 一律存在 |

**解耦就是「有系統地被叫出來」的來源。** 一個信號喚醒範圍內的**所有**伏擊點,所以是一整波
同時動,不是一個一個冒。如果每個伏擊點自己被距離觸發,感覺會是零散的騷擾,不是埋伏。

10 格大約是一個板塊的邊長,所以一個信號大致涵蓋自己和相鄰的板塊。

## 它明確**不做**的事

這些是設計決定,不是還沒做:

- **地圖上不標記。** 信號點和伏擊點都看不見,沒有柵欄、沒有洞、沒有記號。
- **火防女不知道。** 她知道火告訴她的事,伏擊不是火的事。
- **不透露哪些信號點生效。** 玩家只能靠被跳過一次來學,而那是在種子之內學的。
- **不限制一次來幾隻。** 好運壞運,那是這個機制的一部分。
- **不管玩家看不看得到出生。** 那是演出的事,不是機制的事——從地上爬出來、
  從天上掉下來、被具象化,都是伏擊。

## 核心:信號點生不生效是每個種子決定的

這條和種子契約**不衝突**,只要分清楚是哪一層的學習:

| | 保持 | 打掉 |
| --- | --- | --- |
| 同一個種子 | 生效的還是那幾個。死了回來一樣,**學得到** | |
| 不同種子 | | 同一張板塊這次會跳人、下次不會。**學不到「走廊板塊 = 安全」** |

要打掉的是**板塊類型的學習**,不是樓層的學習。

### 沒生效的時候,怪一開始就在

這條讓「沒生效」不等於「什麼都沒發生」:

- **生效**:那些格子在你走過時是空的,信號響了才有東西出來
- **沒生效**:那些怪**一開始就站在那裡**,你正常打

**同一份預算、同一個數量,兩種完全不同的走法。** 玩家事前分不出來:一條站著兩隻狗的走廊,
和一條空的、稍後會生出兩隻狗的走廊。

這也讓預算問題自動消失——**怪的總數兩種情況一樣**,差別只在放的時機。不需要另外算帳,
也和既有的「成群的怪不是更多的怪,是站在一起的怪」是同一條規則。

## 資料長相

兩個都掛在現有的 `enemies` 條目上,不是新的欄位家族。

**伏擊點**——就是現在的 `at` 條目多一個 `nest`:

```js
gully: { weight: 1,
  anchors: { a: 'nest' },
  enemies: { at: 'nest', role: 'charger', n: [2, 3], nest: true },
  art: [ ... ],
},
```

**信號點**——一個新的錨點角色,和敵人無關:

```js
  anchors: { s: 'signal' },
  signal: { at: 'signal', oneIn: 2 },
```

| 欄位 | 意思 |
| --- | --- |
| `enemies.nest` | 這組不在生成時放,等信號。沒有這個欄位就是現在的行為 |
| `signal.at` | 哪個錨點是感測區的中心 |
| `signal.oneIn` | 生效機率的分母。`2` = 一半的種子生效 |

**`role` 對伏擊點是必填的。** 「照層數隨便抽」在走廊裡可能抽到 `blocker`,前後夾擊又沒有
側移空間,那是判死刑不是伏擊。作者必須明講。走廊建議 `charger`(狗):快、脆,
目的是節奏不是傷害。

## 狀態機

```
信號點                          伏擊點
  │                               │
  ├ DEAD(這個種子不生效) ────────→ 怪一開始就站在格子上
  │
  └ LIVE ──玩家進入 5 格──→ FIRE ──→ 喚醒 10 格內所有 nest
                              │        └→ 生出來,醒著,朝玩家移動
                              ↓
                            SPENT
                              │
        坐火(整層復活)─────────┘
```

- 兩個半徑用 Chebyshev(和遊戲其他地方一致)
- `SPENT` 之後不再觸發,直到整層復活
- 一個伏擊點被喚醒過就空了,同樣到休息為止

## 一次,直到休息

這剛好接上既有的篝火契約(休息 = 整層敵人復活),**不用新概念**。

它同時解掉兩個問題:走廊不會變成無限跑步機,死掉之後走回篝火那段路不會變成刑場。

## 生出來的東西

- **醒著**(`aware = true`),而且朝玩家移動。睡著的伏擊等於沒有伏擊。
- 種類由 `role` + 該層深度決定,和現有的 `castFor` 同一張表。
- 站在伏擊點自己畫的格子上。格子被佔住就跳過那一格。

## 演出

機制不管可見性,但**它需要一個事件讓演出掛上去**。

`fx` 現在的事件種類是 `move` / `attack` / `hit` / `knock` / `die`,而 `anim.js` 是**依種類分期**
播的(先全部移動,再全部攻擊,再受傷,再死亡)。伏擊要加一種 `spawn`,排在最前面——
東西先出現,然後才輪到這一回合的其他事。

一句訊息也要有,它是這個機制唯一的聲音(這個遊戲沒有聲音系統,`noise` 陣列只被 renderer
拿去畫地板紋理):

> 「石縫裡有東西鑽出來。」

## 兩個實作上的陷阱

**一、生效與否的骰子不能從樓層的生成流裡抽。**
`placeKeeper` 犯過這個錯:在生成流程中間抽一個亂數,會把它之後的**每一個決定都往後推**,
整座地城變成另一座。當時三次 A/B 比較其實在比兩座不同的地城。

要用衍生的流:`new RNG(`${seed}#${depth}#ambush`)`。這樣加不加這個功能,地圖都是同一張,
而它自己仍然是種子的函數。

**二、被拒絕但不推進回合的動作是無限迴圈。**
這個專案犯過五次(篝火、收招、走進 NPC、機器人撞牛頭人、翻滾)。伏擊本身不接受輸入,
所以不直接踩到,但**機器人**要能處理「本來空的地方突然有敵人」——它每回合重讀狀態,
應該沒事,但這是要測的東西,不是要假設的東西。

## 這會推翻一條寫下來的平衡

`populate.js` 的第二條規則:

> **每層都要有你跑得掉的和跑不掉的。** 否則「跑過去」不是永遠對,就是永遠不可能。

**伏擊專門懲罰「跑過去」。** 這是刻意把天平推向「清乾淨」,不是副作用。
方向是對的(它讓狗有存在的理由),但那條註解要跟著改,不能讓它悄悄地變成假的。

## 驗收:要釘的後果

照這個專案的紀律——**釘後果,不釘機制**:

| 要成立的事 | 怎麼量 |
| --- | --- |
| 同一個種子,生效的信號點一樣 | 同 seed 生成兩次,比對集合 |
| 不同種子,集合會變 | N 個種子,生效率落在 `1/oneIn` 附近,不是全 0 或全 1 |
| 加了這個功能,地圖沒變 | 開關功能,比對 `lvl.tiles` 逐格相同 |
| 走過伏擊點本身不會觸發 | 貼著 nest 走一圈,什麼都沒發生 |
| 進入信號 5 格內會觸發 | 走進去,10 格內的 nest 全部生出來 |
| 生出來的是醒著的、是指定的角色 | 直接讀 |
| 一層樓最多觸發一次(到休息為止) | 跑完一層計數;休息後再跑一次 |
| **沒生效的信號點,那些怪一開始就在** | 未生效 ⇒ 生成後那些格子就有敵人 |
| 兩種情況的敵人總數一樣 | 同一張板塊,生效 vs 不生效,計數相同 |
| 機器人不會卡住 | `failures: 0`,WHYSTALL 沒有新的重複動作 |

每一條都要驗「把規則關掉會不會失敗」。這個專案有三次測試是**因為錯的理由通過**的
(牆擋住、價格擋住、對稱藝術),所以負向驗證不是可選的。

## 還沒決定的

- **5 格和 10 格是起點,不是結論。** 要量。
- **第一層要不要有。** 第一層是教學,被看不見的東西跳可能不是好的第一印象。
- **信號點和伏擊點要不要在同一張板塊上。** 分開放比較像「你觸發了別處的東西」,
  但生成上比較難保證兩者的距離。
